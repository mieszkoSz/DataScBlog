From Notebook to Narrative: Predicting U.S. Business Formation with Random Forests

One of the most interesting things about applied data science is that it often begins with a very practical question: can we predict what happens next? In this project, that question is framed around U.S. business formation activity. Using weekly Business Formation Statistics (BFS) from the U.S. Census Bureau, the notebook explores whether state-level business application activity can be classified as an increase, decrease, or constant relative to the previous week.

At first glance, this looks like a classic machine learning exercise. But what makes the notebook especially valuable is that it does more than simply train a model. It also shows good analytical hygiene: validating source data, reshaping it carefully, testing distributions, separating training and testing chronologically, and interpreting feature importance rather than stopping at a single accuracy number.

The Business Problem

The project focuses on weekly business application counts, specifically BA_NSA, a non-seasonally adjusted measure. The modeling goal is not to predict the exact number of applications. Instead, it asks a more realistic and potentially actionable question:

Can we predict whether current-week state-level business formation is going up, down, or staying roughly constant, without directly using the current week's state-level value?

This framing is smart. Directional classification is often more robust than point prediction, especially in noisy economic time series.

The Data Foundation

The notebook uses two CSV inputs:

  • bfs_us_apps_weekly_nsa.csv — national weekly business formation data
  • bfs_state_apps_weekly_nsa.csv — state-level weekly business formation data

From there, the workflow performs several careful preprocessing steps:

  • Checks that key columns such as Year, Week, and State exist
  • Converts time keys and numeric features into consistent numeric types
  • Validates that there are no duplicate state-week or national week records
  • Pivots state data into a wide format so features become columns such as CA_BA_NSA
  • Merges the state-wide data with U.S.-level features using an outer join

This is a strong foundation. In many real-world ML projects, the difference between success and failure is not the model choice but the quality of upstream data engineering. Here, the notebook treats data validation as a first-class step rather than an afterthought.

Exploration Before Modeling

Before training the random forest, the notebook spends time understanding the data. It plots weekly application trends for the U.S. and checks for missing values across the merged dataset. It also performs normality testing using the Jarque-Bera test and generates histograms and Q-Q plots for selected features.

That exploratory work is useful for two reasons. First, it reveals the structure and imperfections of the data. Second, it reminds us that economic time series are rarely “clean” in the statistical sense. Many features are unlikely to be normally distributed, and that is perfectly acceptable here because tree-based models such as random forests do not rely on normality assumptions the way some linear methods do.

Commentary: the normality tests are analytically interesting, but not strictly necessary for a random forest. Their real value is diagnostic: they help the analyst better understand the behavior of the feature space.

How the Features Are Constructed

The modeling design is one of the most thoughtful parts of the project. For every state and target week, the feature vector includes:

  • The previous 52 weeks of that state’s historical feature values
  • The current-week national U.S. features
  • A one-hot encoded state identifier

The target label is derived from whether that state's current BA_NSA is lower, equal to, or higher than the prior week. These become the three classes:

  • DECREASED
  • CONSTANT
  • INCREASED

This setup captures both local temporal memory and national context. In plain terms: the model is allowed to look at how a given state has behaved over the last year, while also seeing what is happening nationally in the same week.

Why the Train/Test Split Matters

One of the most important methodological choices is the chronological split:

  • Training: 2006–2023
  • Testing: 2024–2026

This is exactly what we want in a forecasting-style problem. Random shuffling would create leakage across time and make evaluation overly optimistic. By holding out future years, the notebook tests whether the model generalizes to genuinely unseen periods.

Missing predictor values are imputed using training-set medians only, another good practice because it avoids contaminating the training pipeline with information from the future.

The Model: Random Forest Classification

The chosen model is a RandomForestClassifier with 100 trees and a maximum tree depth of 7. That is a sensible balance between expressive power and overfitting control. Random forests are especially attractive here because they:

  • Handle nonlinear relationships well
  • Are robust to mixed feature distributions
  • Can naturally rank feature importance
  • Require relatively little feature scaling or transformation

The notebook evaluates the model both on the training data and on the held-out test period using:

  • Overall multiclass accuracy
  • Confusion matrices
  • Per-class recall
  • Macro recall across the three classes

This is a thoughtful evaluation set. Accuracy alone can hide class imbalance or weak performance on one particular direction. Reporting recall per class makes the assessment more transparent.

Interpreting the Results

The PDF conversion shows the workflow and evaluation logic clearly, though it does not expose the actual final accuracy numbers in the extracted text. Even so, the project already demonstrates a mature structure for answering its core questions:

  1. Can state-level business formation direction be predicted?
  2. Which features matter most?

The feature importance analysis uses mean decrease in impurity (MDI) from the fitted random forest. Features are grouped into:

  • Lagged state features
  • Current-week national features
  • State identity indicators

This grouping is valuable because it moves the analysis beyond a raw top-20 list and asks a more strategic question: does predictive strength come mainly from recent local history, national macro signals, or simply persistent state-specific patterns?

Commentary: if lagged state features dominate, that suggests local momentum and seasonality drive most of the signal. If national contemporaneous features rank highly, it implies broader macro conditions meaningfully influence state-level business creation behavior.

Conclusion

The most important 3 features for the classification of next week state level business formation applications increas/decrease (or no change) are the following: - National current CBA_NSA - National current HBA_NSA - Previous week state CBA_NSA With over 62% out of sample accuracy the model is not terrible, however it only slightly outperforms a naive estimator (random) it should be further compared to another naive benchmark like mean() based estimator.
